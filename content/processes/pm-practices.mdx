Трекер задач холдинга — self-hosted Plane (`plane.bbm.academy`, см.
[Экосистема](/ecosystem)). Эта страница — командные практики; технический
runbook (доступы, API-нюансы, CLI) — `bbm/docs/plane-operations.md`.

## Два workspace

| Workspace | Назначение | Проекты |
|---|---|---|
| `bbm` | Холдинг: инфра, тулинг, бизнес, сайт, события | BBMP / BBMB / BBMS / BBME |
| `doctor-school` | Продукт Doctor.School (релаунч) | DSP / DSC / DSM / DSO |

Расшифровки кодов проектов — канонический реестр `ssot/abbreviations.yaml`.

**Правило размещения:** BBM-инфра и тулинг (Mattermost, Plane, мониторинг, KB,
AI-агенты, бэкапы) → workspace `bbm`, проект BBM Platform. Работа по продукту
Doctor.School → `doctor-school`. ⚠️ DSO («Doctor School Operations») — операции
*продукта* (юридика/финансы/найм/релиз), это не дом для BBM-инфры.

## Задача существует до работы

Под любую содержательную работу должна существовать отслеживающая задача —
если её нет, исполнитель заводит её сам (workspace по правилу размещения,
модуль обязателен). Задачи не оформляются задним числом.

## Формат задачи

- **Название:** глагол совершенного вида + конкретный объект.
  ✅ «Подготовить КП для инвесторов (CAC, LTV)» · ❌ «План КП».
  Milestones — формат «🎯 Milestone: “состояние”».
- **Описание:** Цель / Готово, когда (AC) / Что сделать (шаги) / Блокеры /
  Ссылки. ⚠️ **Owner в описании не указывается** — и вообще ничто, для чего в
  Plane есть нативное поле: ответственный живёт в `assignees`, срочность в
  `priority`, сроки в `start/target date`, принадлежность майлстоуну в
  `parent`, связи в relations. Проза расходится с полями через день после
  первой правки и ломает фильтры, выгрузки и оценку загрузки людей.
- **Модуль обязателен** — задача без модуля висит в `None`; если задача не
  ложится ни в один модуль, вероятно, она не в том проекте.
- **Производственные цепочки** разбиваются на sub-issues с числовой
  нумерацией `1.`, `2.`, `3.` в title; каждый sub-issue — со своим owner,
  start, target и AC.
- Priority и assignee — нативные поля Plane (не дублировать лейблами).
  Лейблы: `milestone / deliverable / recurring / v1 / v2 / v3`.

## Выбор статуса

Статус выставляется явным решением, а не остаётся дефолтом инструмента
(`create` в CLI по умолчанию кладёт задачу в `Backlog`).

| Статус | Когда |
|---|---|
| `In Progress` | работа идёт прямо сейчас |
| `Todo` | принята в работу, ждёт очереди в текущем горизонте / OKR |
| `Backlog` | **легитимно:** задача сознательно деприоритизирована — вне текущих OKR, отложена без горизонта |
| `Cancelled` | решено не делать (причина — в комментарии) |

Брак — не сам `Backlog`, а `Backlog`, доставшийся задаче по умолчанию вместе с
пустой панелью Properties. У осознанно отложенной задачи заполнены assignee,
priority (`low`), модуль и parent; дат может не быть — выдуманные сроки у
отложенной задачи хуже их отсутствия. При подъёме в `Todo` даты проставляются
в тот же момент.

## Жизненный цикл задачи

1. **В начале работы** — перевести в `In Progress`.
2. **По ходу** — промежуточные комментарии при ключевых решениях, пересмотре
   scope, рисках-блокерах (не каждый шаг — только важное для других).
3. **В конце сессии:** завершена → `Done` + обязательный результирующий
   комментарий; не завершена → комментарий «где остановились / что осталось».
4. **Результирующий комментарий:** Артефакты (пути/ID) · Сделано (3–6
   пунктов) · Open questions / вне scope · Что разблокировано.
5. Задача с несмерженным PR не переводится в `Done`.

## Планирование

- **Backward planning** от целевой даты, 5-дневка (Сб/Вс — выходные).
- Для каждой пары зависимых задач: `predecessor.target_date <
  successor.start_date`; same-day переходы допустимы для коротких артефактов.
- Cycles («Спринт N») синхронизированы по проектам workspace.
- **Ежедневный пинг:** одно сообщение в общий чат с разбивкой по людям
  (🔥 ГОРИТ → блоки `@Имя` → ❓ что блокирует / закрыли).

## Ревью и гейты

Ревью выполняет независимый агент/участник, не автор. Ручной гейт владельца —
только эксклюзивная зона (деньги, доступы, стратегия); спорные факты помечаются
`TODO(Антон)` в артефакте и не блокируют merge.
