---
title: Как добавить книгу в базу знаний
description: Подготовка форматов, публикация файлов, страница библиотеки и проверка результата
---

Этот runbook описывает полный путь от полученных исходников до опубликованной страницы в разделе
[Библиотека](/library). Для содержательной правки сначала создаётся задача в Plane, затем изменения
проходят через PR в `bbm-academy-org/bbm-kb`.

## 1. Проверить входные материалы

До обработки зафиксировать в задаче Plane:

- автора, название, язык, издательство и год издания;
- какие исходники получены: EPUB, PDF, MP3 по главам, обложка;
- кто читает аудиоверсию, если это известно;
- подтверждение владельца задачи, что материалы можно разместить для команды.

Исходники считать неизменяемыми: конвертировать только копии в отдельном выходном каталоге.

> `bbm-portal-media` — публичный бакет. Прямые ссылки на объекты открываются без SSO, хотя сама KB
> защищена входом. Не загружать туда персональные данные, конфиденциальные документы и материалы,
> для которых не подтверждено право распространения.

## 2. Выбрать имена и место хранения

Для одной книги используется отдельный префикс:

```text
knowledge-base/books/<author-slug>/<book-slug>/
```

Имена объектов — ASCII, lowercase, kebab-case. Рекомендуемый базовый шаблон:

```text
<author>-<book>-<language>.<ext>
```

Пример:

```text
knowledge-base/books/frederic-laloux/reinventing-organizations/
frederic-laloux-reinventing-organizations-ru.epub
frederic-laloux-reinventing-organizations-ru.m4b
frederic-laloux-reinventing-organizations-ru-mp3.zip
cover.jpg
```

Страница книги живёт в `content/library/<author>-<book>.mdx`.

## 3. Подготовить читаемые форматы

Минимальный набор:

| Формат | Назначение |
|---|---|
| EPUB | Основной формат для Apple Books, Google Play Books, PocketBook и Send to Kindle |
| PDF | Компьютер, планшет, печать |
| FB2 | PocketBook, Cool Reader и другие распространённые читалки |
| AZW3 | Ручная загрузка на Kindle |
| MOBI | Старые модели Kindle и совместимые приложения |

Для конвертации использовать Calibre CLI. Исходный EPUB сначала скопировать под итоговым именем,
затем задать одинаковые метаданные и обложку во всех вариантах:

```powershell
$SourceEpub = "D:\incoming\book.epub"
$OutDir = "D:\books\author-book"
$Base = "author-book-ru"
$Author = "Имя автора"
$Title = "Название книги"
$Cover = Join-Path $OutDir "cover.jpg"

Copy-Item -LiteralPath $SourceEpub -Destination (Join-Path $OutDir "$Base.epub")

foreach ($format in @("pdf", "fb2", "azw3", "mobi")) {
  ebook-convert $SourceEpub (Join-Path $OutDir "$Base.$format") `
    --authors $Author --title $Title --language ru --cover $Cover
}

ebook-meta (Join-Path $OutDir "$Base.epub") `
  --authors $Author --title $Title --language ru --cover $Cover
```

Проверить, что каждый файл открывается и содержит правильные название, автора, язык и обложку.
PDF дополнительно проверить визуально: обложка, первые страницы, несколько страниц из середины и
последняя страница. Текст не должен обрезаться, перекрываться или превращаться в пустые квадраты.

## 4. Подготовить аудио

Если исходник состоит из MP3-глав, публикуются два варианта:

- **M4B** — один файл с главами и обложкой для приложений аудиокниг;
- **ZIP** — исходные MP3 и обложка для максимальной совместимости.

Сначала отсортировать MP3 по имени и проверить теги. Для M4B сформировать:

- `audio-concat.txt` — список файлов для concat demuxer;
- `chapters.ffmeta` — главы с `TIMEBASE=1/1000`, накопительными `START`/`END` и названиями из тегов;
- итоговый файл AAC с обложкой:

```powershell
ffmpeg -f concat -safe 0 -i audio-concat.txt `
  -i chapters.ffmeta -i cover.jpg `
  -map 0:a -map 2:v -map_metadata 1 `
  -c:a aac -b:a 64k -c:v copy -disposition:v attached_pic `
  -movflags +faststart author-book-ru.m4b
```

ZIP создавать только после завершения FFmpeg, чтобы процесс кодирования не держал исходники:

```powershell
Add-Type -AssemblyName System.IO.Compression.FileSystem
[IO.Compression.ZipFile]::CreateFromDirectory(
  "D:\incoming\author-book-mp3",
  "D:\books\author-book\author-book-ru-mp3.zip",
  [IO.Compression.CompressionLevel]::Optimal,
  $false
)
```

Проверки M4B:

- длительность близка сумме длительностей MP3;
- число глав совпадает с числом MP3;
- присутствуют AAC-аудио и встроенная обложка;
- без ошибок декодируются фрагменты в начале, середине и конце.

ZIP нужно открыть программно и полностью прочитать каждую запись, а не ограничиваться просмотром
списка файлов.

## 5. Загрузить файлы

Исполнитель должен иметь доступ к Timeweb S3. Креды передаются только через разрешённое локальное
окружение или секрет-хранилище; их нельзя вставлять в задачу Plane, чат, shell history, репозиторий
или PR.

Загрузка выполняется в публичный бакет `bbm-portal-media`, endpoint
`https://s3.twcstorage.ru`. Для каждого файла явно задаётся MIME-тип:

| Расширение | MIME-тип |
|---|---|
| `.jpg` | `image/jpeg` |
| `.epub` | `application/epub+zip` |
| `.pdf` | `application/pdf` |
| `.fb2` | `application/x-fictionbook+xml` |
| `.azw3` | `application/vnd.amazon.mobi8-ebook` |
| `.mobi` | `application/x-mobipocket-ebook` |
| `.m4b` | `audio/mp4` |
| `.zip` | `application/zip` |

Пример с уже настроенными временными переменными AWS:

```powershell
$Prefix = "knowledge-base/books/author/book"
aws s3 cp $File "s3://bbm-portal-media/$Prefix/$Name" `
  --endpoint-url https://s3.twcstorage.ru `
  --content-type $ContentType `
  --only-show-errors
```

Не перезаписывать существующий ключ, пока не проверено, что это та же книга и новая версия должна
заменить старую.

## 6. Создать страницу книги

Добавить страницу в `content/library/` и ссылку на неё в `content/library/index.mdx`.
На странице указать краткое описание, автора, издательство, год, чтеца и таблицы скачивания.

Внешнюю обложку вставлять HTML-тегом с фактическими размерами:

```mdx
<img
  src="https://s3.twcstorage.ru/bbm-portal-media/knowledge-base/books/author/book/cover.jpg"
  alt="Обложка книги"
  width="500"
  height="500"
/>
```

Не использовать для внешней обложки Markdown-синтаксис `![...](...)`: Fumadocs пытается определить
размер картинки во время CI и сборка может упасть, даже если S3-ссылка открывается в браузере.

В таблице форматов указать назначение, размер и прямую ссылку. Если читатель не знает, что выбрать,
рекомендовать EPUB; для аудио — M4B, а ZIP оставить как вариант максимальной совместимости.

## 7. Проверить до PR

Для каждого опубликованного объекта проверить:

1. публичный `HEAD` возвращает `200`;
2. `Content-Length` совпадает с локальным размером;
3. `Content-Type` соответствует таблице выше;
4. для M4B и ZIP запрос диапазона возвращает `206` и нужное число байт;
5. на странице нет ссылок на отсутствующие файлы.

Затем выполнить:

```bash
npm ci
npm run build
git diff --check
```

Успешная локальная сборка не заменяет CI: Linux-сборка PR обязательна.

## 8. Опубликовать

1. Создать ветку с номером Plane-задачи в коммитах.
2. Открыть PR в `bbm-academy-org/bbm-kb`.
3. Дождаться зелёного `build`.
4. После merge дождаться успешных `build`, `pr-guard` и `deploy` на `main`.
5. Проверить, что HTML страницы появился в `/var/www/kb.bbm.academy` и публичный URL страницы
   переводит неавторизованного пользователя в SSO.
6. В задаче Plane оставить ссылку на страницу, PR, deploy-run и результаты проверки файлов;
   перевести задачу в `Done`.

## Критерий готовности

Книга считается опубликованной, когда:

- исходники сохранены без изменений;
- все заявленные форматы созданы и проверены;
- объекты доступны по публичным ссылкам с правильными размерами и MIME-типами;
- страница книги присутствует в библиотеке;
- PR смержен, production deploy зелёный;
- живая страница доступна через SSO, а задача Plane закрыта с доказательствами.

Удаление или замена опубликованных объектов выполняется отдельно: сначала найти все ссылки на ключ,
получить явное подтверждение владельца и только затем менять S3 и страницу через новый PR.
