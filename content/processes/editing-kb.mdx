Сайт `kb.bbm.academy` — статическая выгрузка этого репозитория
(`bbm-academy-org/bbm-kb`, приватный GitHub). Править сайт = править репо;
**любая правка попадает в `main` только через Pull Request** — после merge
сайт обновляется автоматически.

## 1. Доступ

- **Чтение KB:** `https://kb.bbm.academy` — вход через SSO
  (`id.bbm.academy`), учётка = рабочий email `@bbm.academy`.
  Пароль выдаёт Tech Lead; при первом входе система потребует его сменить.
- **Правки:** нужен доступ к GitHub-репо `bbm-academy-org/bbm-kb`
  (приглашение в организацию — у Tech Lead). Клон:

  ```bash
  git clone git@github.com:bbm-academy-org/bbm-kb.git
  cd bbm-kb
  git config core.hooksPath .githooks   # локальный guard от пуша в main
  ```

## 2. Два способа правки

**Через AI-сессию (основной).** Открыть агентскую сессию (Claude Code и т.п.)
в клоне репо и поставить задачу словами: «поправь страницу X», «добавь факт Y».
Агент читает `AGENTS.md` (правила SSOT, механика) и сам делает ветку, правку,
проверку сборки и PR. От человека — только сформулировать правку и померджить
PR после ревью.

**Руками.** Тоже допустимо:

```bash
git checkout -b fix/moya-pravka
# правка: content/**/*.mdx — нарратив; ssot/facts/*.yaml — канонические факты
npm ci && npm run build   # сборка должна быть зелёной
git commit -am "Поправил X"
git push -u origin fix/moya-pravka
gh pr create --fill        # или через веб-интерфейс GitHub
```

Куда что класть — два правила из `AGENTS.md`:

- **`ssot/` = канон** (команда, сущности, сервисы, глоссарий, аббревиатуры) —
  факты меняются только здесь; страницы ссылаются на канон, не копируют его.
- **`content/` = нарратив** (страницы сайта, MDX) — текст, который объясняет
  и связывает факты.

## 3. PR и что происходит дальше

1. PR открывает CI-джоб `build`: собирает статический экспорт
   (`npm run build`) — красный билд блокирует merge.
2. **pr-guard:** прямой пуш в `main` запрещён конвенцией; CI краснеет на
   прямом пуше, локальный pre-push hook (`.githooks/`) не даст запушить
   случайно. Серверной branch protection нет (GitHub Free) — дисциплина PR
   обязательна.
3. После merge в `main` — **автодеплой**: артефакт билда уезжает на хост и
   `kb.bbm.academy` обновляется в течение пары минут. Изменения `ssot/facts/*`
   дополнительно пропагируются в потребителей (публичный сайт) отдельным джобом.

## 4. Смежные правила

- [Нейминг документов (chain-notation)](/processes/naming) — как называть
  страницы и документы.
- [PM-практики (Plane)](/processes/pm-practices) — содержательная правка
  делается под задачу в Plane, не «мимоходом».
- Секреты (ключи, токены, пароли) в репо и в PR не попадают никогда.
